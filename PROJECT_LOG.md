# Журнал проекта — «Он бы тебе сказал»

Этот файл — краткая история решений и прогресса. Веди его при каждой
значимой сессии, чтобы новая сессия Claude Code могла быстро восстановить
контекст без объяснений от пользователя.

## 2026-08-13 — Инициализация проекта

**Что сделано:**
- Создана базовая структура: `index.html`, `style.css`, `script.js`,
  `README.md`, `.gitignore`.
- Реализован полный игровой цикл: старт → случайная категория → запись
  голоса (10 сек, `MediaRecorder` + визуализация `AnalyserNode` на canvas) →
  воспроизведение (play/pause) → «Отправить» (заглушка, тост) →
  «Следующий раунд» (новая категория, без повтора текущей).
- 10 категорий предметов на русском (кухня, сумка, ванная, рабочий стол,
  карман куртки, холодильник, под кроватью, машина, полка с обувью, ящик с
  зарядками) — список зашит в `CATEGORIES` в `script.js`.
- Тёмная тема, акценты жёлтый `#F4B942` и розовый `#E8598B`, заголовки —
  Space Grotesk, текст — Inter (через Google Fonts CDN).
- Добавлена кнопка «Отменить» на экране записи (не было в исходном
  ТЗ, но нужна для UX — если пользователь передумал или закрыл доступ к
  микрофону по ошибке).
- Инициализирован git-репозиторий, сделан первый коммит.

**Ключевые решения:**
- Чистый HTML/CSS/JS без фреймворков и без шага сборки — специально под
  Vercel (Framework Preset: Other, output = корень репозитория).
- `MediaRecorder` mime-type выбирается через `isTypeSupported` с фолбэком
  (`audio/webm;codecs=opus` → `audio/webm` → `audio/mp4` → `audio/ogg`), т.к.
  поддержка отличается между браузерами (особенно Safari/iOS).
- Таймер записи считается через `performance.now()`, а не просто
  `setInterval`, чтобы визуальный прогресс-бар был плавным и не зависел от
  дрифта таймера.
- Экран «Следующий раунд» возвращает сразу на экран категории (шаг 2), а не
  на стартовый экран — так короче игровой цикл между раундами.

**Известные ограничения / TODO на будущее:**
- Кнопка «Отправить» — просто заглушка (тост), реальной отправки/бэкенда
  нет. Если понадобится — нужен сервер или serverless function на Vercel для
  приёма аудио, плюс место для хранения клипов (например Vercel Blob).
- Нет тестов (для чистого HTML/CSS/JS проекта без сборки — осознанно не
  добавлялись).
- Домен `fruktic.com` пока не привязан — ждём, когда пользователь создаст
  репозиторий на GitHub и подключит Vercel.
- Иконка/favicon — временный inline SVG-эмодзи, можно заменить на
  полноценный набор иконок при желании.

**Статус:** репозиторий связан с GitHub
(`https://github.com/futurefruit/a-tvoy-otvet-.git`, ветка `main`), первый
push сделан. Следующий шаг — подключить репозиторий к Vercel и привязать
домен `fruktic.com`.

## 2026-08-13 — Локализация интерфейса (RU / UA)

**Что сделано:**
- Добавлена поддержка двух языков интерфейса: русский (по умолчанию) и
  украинский. Переведены заголовок, весь текст экранов, все 10 категорий,
  тексты кнопок, сообщение об ошибке доступа к микрофону, тост «клип готов
  к отправке» и aria-label кнопки play/pause.
- Новый файл `i18n.js` — словарь `STRINGS = { ru: {...}, uk: {...} }` и
  функции `t(key)` (достаёт перевод, поддерживает вложенные ключи вида
  `categories.kitchen`), `setLanguage(lang)` (мгновенное переключение без
  перезагрузки), `applyStaticTranslations()` (декларативно обновляет всё,
  что размечено атрибутами `data-i18n` / `data-i18n-attr` в `index.html`).
  Добавление третьего языка (например английского) — это просто новый ключ
  `en` в `STRINGS`, остальной код трогать не нужно.
- Новый файл `storage.js` — обёртка `window.storage` (`getItem` /
  `setItem` / `removeItem`) для сохранения выбора языка между визитами.
  **Важно:** по ТЗ это намеренно НЕ `localStorage` — внутри используется
  `document.cookie` напрямую (cookie на 365 дней), но остальной код
  обращается только к `window.storage`, так что транспорт можно сменить в
  одном месте, не трогая игровую логику.
- Определение языка при первом визите (`detectInitialLanguage()` в
  `i18n.js`): 1) если в `window.storage` уже есть сохранённый ручной выбор —
  используется он; 2) иначе проверяются `navigator.languages` /
  `navigator.language` — если какой-то из них начинается с `"uk"`,
  включается украинский; 3) во всех остальных случаях — русский по
  умолчанию.
- В `script.js` категории теперь хранятся как ключи (`CATEGORY_KEYS`:
  `kitchen`, `bag`, `bathroom`, `desk`, `jacket`, `fridge`, `underBed`,
  `car`, `shoeShelf`, `chargerDrawer`), а не готовый текст — сам текст на
  нужном языке подставляется через `t()` в момент отрисовки. Это позволяет
  мгновенно перерисовать уже показанную категорию при переключении языка
  прямо посреди раунда.
- В `index.html` добавлен переключатель языка (кнопки `RU` / `UA`) в
  верхнем углу шапки, подсвечивает активный язык.
- Порядок подключения скриптов в `index.html`: `storage.js` → `i18n.js` →
  `script.js` (`i18n.js` должен быть загружен и выполнен до `script.js`,
  т.к. `script.js` использует глобальную функцию `t()`).

**Ключевые решения:**
- `window.storage` вместо `localStorage` — прямое требование пользователя.
  Возможные причины (не уточнялись явно, но стоит иметь в виду в будущих
  сессиях): политика хостинга/приватности, желание держать транспорт
  абстрагированным для будущей серверной синхронизации, или другие
  соображения пользователя. Выбор сделан пользователем осознанно через
  уточняющий вопрос (варианты: cookies-обёртка / голый объект в памяти /
  sessionStorage / внешняя среда) — выбрана cookies-обёртка, т.к. только
  она реально выполняет требование «запоминать выбор при следующем визите».
- Тексты переводятся двумя механизмами: декларативно через
  `data-i18n`/`data-i18n-attr` в разметке (для статичных элементов) и
  вручную в `script.js` через слушатель `document.addEventListener("app:languagechange", …)`
  (для того, что генерируется в рантайме: текст категории на всех трёх
  экранах, сообщение об ошибке микрофона, aria-label плеера).

**Известные ограничения / TODO на будущее:**
- См. предыдущую запись (заглушка «Отправить», нет тестов, домен ещё не
  привязан).
- Если понадобится английский — добавить `en` в `STRINGS` (i18n.js) и
  добавить кнопку `EN` в `.lang-switch` (index.html), больше ничего менять
  не нужно.

## 2026-08-14 — Английский язык, баг с иконкой, платные заглушки (подсказки + голосовые фильтры)

Три отдельные задачи за одну сессию — фиксирую всё пунктами ниже.

### 1. Добавлен английский (EN)

- В `STRINGS` (i18n.js) добавлен третий язык `en` — переведены абсолютно
  все ключи, включая все 10 категорий и (забегая вперёд, см. пункт 3) все
  40 фраз-подсказок.
- Название игры на английском — «It Would Tell On You» (каламбур на
  «tell on someone» — «донести/выдать» — хорошо ложится на смысл игры).
- Переключатель языка в шапке теперь 3 кнопки: `RU` / `UA` / `EN`.
- Логика автоопределения (`detectInitialLanguage()` в i18n.js) расширена:
  сохранённый в `window.storage` ручной выбор — приоритет; иначе если
  `navigator.languages`/`navigator.language` начинается с `"uk"` →
  украинский; начинается с `"ru"` → русский; иначе (включая случаи, когда
  язык браузера не определён) → английский по умолчанию.
- Проверено скриптом (запускал i18n.js в vm-песочнице в Node и сравнивал
  наборы ключей всех трёх языков рекурсивно) — расхождений в ключах между
  `ru`/`uk`/`en` нет, у каждой из 10 категорий по 4 фразы-подсказки на
  каждом языке.

### 2. Починен баг с иконкой на стартовом экране

- Проблема: эмодзи 🪞 (зеркало) между подзаголовком и кнопкой на некоторых
  системах/шрифтах рендерился пустым прямоугольником (нет глифа в
  системном emoji-шрифте).
- Решение: эмодзи заменён на инлайн-SVG иконку — речевой пузырь с тремя
  точками («думает / вот-вот скажет»), обводка градиентом жёлтый→розовый
  (фирменные цвета). SVG рендерится одинаково во всех браузерах, зависимости
  от системных emoji-шрифтов больше нет. Класс `.hero-emoji` заменён на
  `.hero-icon` в `style.css`.
- Остальные эмодзи в интерфейсе (🎙️, 🔒, 🎵, 🐿️, 🤖) — сохранены как есть:
  это широко поддерживаемые Unicode-эмодзи из базового набора, явно
  запрошены пользователем для новых платных фич (см. пункт 3), проблем с
  рендером у них не наблюдалось.

### 3a. Шпаргалка с репликами (заглушка платной фичи)

- На экране записи под таймером — кнопка «Подсказать» (`btn-hint`) с
  бейджем `PRO` и иконкой 🔒, оформлена как платная фича (градиентная
  обводка), но по клику **сразу** показывает случайную реплику — без
  проверки оплаты, как и просили. Реальная оплата — задача на будущее.
- Для каждой из 10 категорий написано по 4 забавных фразы от лица
  предмета, на русском, украинском **и английском** (английский не
  запрашивался явно в этой части ТЗ, но добавлен для консистентности —
  раз интерфейс теперь трёхъязычный, странно было бы оставлять
  EN-пользователя без подсказок или молча показывать ему русский текст).
  Все фразы лежат в `STRINGS[lang].cheatLines.<categoryKey>` (массив из 4
  строк) в i18n.js.
- `showHint()` (script.js) берёт `t(\`cheatLines.${categoryKey}\`)` и
  выбирает случайный элемент; `resetHint()` скрывает блок подсказки —
  вызывается при входе на экран записи (новый раунд/новая попытка) и при
  смене языка (чтобы не показывать реплику не на том языке).

### 3b. Голосовые фильтры на экране воспроизведения

- Под плеером — три кнопки-переключателя: «Обычный» 🎵 / «Писклявый» 🐿️ /
  «Робот» 🤖 (`filter-row` / `filter-btn` в index.html и style.css).
- Реализация в script.js (`ensureFilterGraph()`, `applyVoiceFilter()`):
  - **Обычный** — `audioClip.playbackRate = 1`.
  - **Писклявый** — `audioClip.playbackRate = 1.5` (меняет и скорость, и
    высоту тона одновременно — самый дешёвый и надёжный способ без
    сложного pitch-shifting).
  - **Робот** — граф Web Audio: `MediaElementSourceNode` → parallel dry/wet
    пути. Wet-путь = `WaveShaperNode` с кривой-лестницей (имитация
    bitcrusher, грубое квантование сигнала) → `GainNode`, чьё значение
    `gain` модулируется синус-осциллятором ~35 Гц, подключённым напрямую
    к `AudioParam` этого гейна (классический приём ring-модуляции в Web
    Audio без отдельного multiply-узла). Переключение между dry/wet —
    плавный `setTargetAtTime` на гейнах, чтобы не было щелчков.
  - Граф создаётся один раз лениво (`MediaElementSourceNode` нельзя
    пересоздать на одном и том же `<audio>` элементе) и живёт всё время
    жизни страницы; `resetVoiceFilter()` возвращает состояние к
    «Обычный» при входе на экран воспроизведения (новая запись).
  - `AudioContext.resume()` вызывается внутри обработчиков клика (клик по
    фильтру или по play) — то есть всегда в ответ на явный жест
    пользователя, чтобы не упереться в autoplay-политику браузеров.
- **Важное упрощение, сделанное осознанно:** фильтр применяется только к
  *воспроизведению* в реальном времени через Web Audio Graph — сам Blob
  записи не перекодируется/не рендерится офлайн с применённым эффектом.
  Так как «Отправить» по ТЗ — это всё ещё UI-заглушка без реальной
  отправки файла, «участие фильтра в Отправить» реализовано как: тост
  показывает название выбранного фильтра, например «Клип готов к
  отправке! 🎉 (Робот)». Если в будущем «Отправить» станет реальной
  отправкой файла — тогда потребуется дорендерить эффект в сам Blob через
  `OfflineAudioContext` (декодировать записанный blob, прогнать через тот
  же граф офлайн, закодировать обратно в WAV/webm) — сейчас этого нет.

**Известные ограничения / TODO на будущее:**
- Голосовые фильтры не сохраняются в отправляемый файл (см. упрощение
  выше) — только в тексте тоста.
- Реальная оплата подсказок не подключена — кнопка всегда открывает
  контент.
- Домен `fruktic.com` и Vercel всё ещё не подключены (см. предыдущие
  записи).
